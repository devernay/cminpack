# Problems excluded from the FORTRAN-reference cross-check gate
# (examples/crosscheck.py and the CMake crosscheck_* tests).
#
# The gate (see examples/driver_check.py) checks, on every intensive-driver
# problem the committed FORTRAN reference converged on (exit parameter
# info < 5), that this build converged too -- failing if this build's solver
# reports non-convergence (info >= 5) OR if FORTRAN reached a near-zero residual
# but this build did not.
#
# A few deliberately-extreme More/Garbow/Hillstrom problems (the 10x/100x
# starting points) sit on a knife's edge where a one-ULP, compiler-dependent
# difference (FMA contraction) flips a trust-region accept/reject decision and
# sends the two runs down different, equally valid paths. Requiring a match
# there is not meaningful, so they are listed here. Which problems flip depends
# on the compiler's default FMA contraction and on the optimization level:
# Apple clang contracts even at -O0, and GCC contracts by default wherever the
# target has FMA instructions (e.g. aarch64, but not baseline x86-64). The list
# below covers Apple clang (Release and Debug) and GCC on arm64. Building with
# -ffp-contract=off, cminpack passes the gate with no exclusions at all.
#
# Format: one "nprob/dimension" per line. When the gate fails it prints the
# problem as "nprob/dim"; add that token here (it then never fails the build).
#
# 6/4: Powell singular function (dim 4), a zero-minimum problem. The FORTRAN
#      reference exits info=4, this build info=5; both drive the residual to
#      ~1e-33, so the difference is only the stop code.
# 8/30: variably-dimensioned function (dim 30). On Apple clang this build
#      diverges (residual ~83, info=4) where FORTRAN reaches ~0 (info=1); on
#      Linux GCC both converge. A last-bit FMA coin-flip -- see the analysis in
#      docs/crosscheck-8-30-analysis.md.
# 8/40: the same problem 8 at dim 40 (standard starting point). With gcc-16
#      Release on arm64 and with Apple clang Debug, hybrd and hybrj stall at a
#      residual of ~128 (info=4) where FORTRAN reaches ~1e-13 (info=1). On
#      arm64, the original FORTRAN built with gfortran -O2 stalls in the same way.
# 6/9: Watson function (dim 9). With Apple clang Debug, hybrd from the 10*x0
#      start stops at a residual of ~0.63 where FORTRAN reaches ~3e-13 (the
#      token excludes both starting points of 6/9). On arm64, the original
#      FORTRAN built with gfortran -O2 fails it too (examples/crosscheck_matrix.sh).
